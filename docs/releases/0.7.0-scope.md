# 0.7.0 release scope

Minor release that closes the gaps found while planning TaskForge's move from Chakra UI v3 to OneSmallUI
(TaskForge is the first app built on the library, and its case study). Everything is additive: no existing
prop, class or token changes meaning.

## In scope

1. **Router-aware links.** `Button` (with `href`) and `BreadcrumbItem` accept `as` (an element type such as
   Next.js `Link` or a router link that takes `href`) and `render` (full control), matching the existing
   `SidebarItem`, `CommandPalette` and `TreeView` shape. Without them a client-side router does a full page load.
2. **Fonts and coexistence docs.** The Theming page shows how to point `--os-font-sans` and
   `--os-font-display` at an app font, and how to run OneSmallUI beside a layered library (Chakra UI v3) during
   a screen-by-screen migration.
3. **Company theme generation** (ROADMAP item 3): a script that turns brand colors into a complete, checked
   light and dark theme (themes.json-shaped JSON, CSS and a Sass map), sharing one contrast pair list with
   `check-contrast.mjs`, with fixtures for a passing brand, a failing brand and a dark-only problem.
4. **Icons TaskForge needs** that the set lacks, drawn as originals under the existing icon rules. Brand marks
   (GitHub, LinkedIn) stay out of scope; apps keep their own for those.

## Out of scope

- Selective CSS output and the package footprint work (ROADMAP items 1 and 2).
- Publishing. The maintainer publishes with the `Publish package` workflow after the release PR merges, as
  for 0.6.1 (see [docs/ci-cd.md](../ci-cd.md)); nothing in this scope is published or attested until then.

## Acceptance

- `npm run check`, `npm run build`, `npm run test:a11y`, `npm run test:layout` and `npm run test:consumer`
  pass on the release commit.
- New behavior has unit tests with axe checks, docs examples and CHANGELOG entries.
