## E. Provenance: the conflict and the smallest resolution

**Conflict.** `docs/RELEASING.md` (before this PR) called provenance "optional, recommended". The hub's
Definition of Done, Tier 2 gate 19 `release-provenance`, requires "npm `--provenance` or signed tags where the
channel supports it". npm supports provenance when publishing from GitHub Actions, and git supports signed tags,
so the gate applies. 0.6.0 has neither (section A). The hub wins: this PR rewrites the RELEASING section to make
provenance required from the next release, and makes `git tag -s` the default tag command.

**What cannot change.** npm attestations are attached only at publish time, and the existing tag is not moved, so
0.6.0 itself stays without provenance whatever is decided.

**Compensating evidence already in hand.** The npm integrity equals the candidate recorded before publication, a
clean rebuild from `v0.6.0` reproduces the published tarball byte for byte, and the owner-annotated tag points at
the verified commit.
