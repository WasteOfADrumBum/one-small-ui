# 0.6.1 release scope

Patch release to publish the existing 0.6.0 library with npm provenance through GitHub Actions trusted publishing. Component APIs are unchanged; one behavior fix was added after the release PR (nested dialogs closing together on Escape, see the CHANGELOG). The 0.6.0 package remains published without npm provenance; this release does not alter its history.

Before publishing, confirm the CI checks pass for the merged release commit. In npm package settings, add a GitHub Actions trusted publisher with owner `WasteOfADrumBum`, repository `one-small-ui`, workflow filename `publish.yml`, environment `npm-publish`, and allow `npm publish`. Do this shortly before publishing: new trusted publishers expire if unused after two days.

Run the `Publish package` workflow manually on `main` after the release PR is merged, with `candidate_sha` set to the merged commit, `expected_version` 0.6.1 and `dry_run` first left on (see [docs/ci-cd.md](../ci-cd.md)). The workflow requires a green CI run for that exact commit on `main`, takes the tarball CI built and checked, rebuilds it to confirm the digest, runs the consumer tests on it, and with `dry_run` off publishes that same file with npm provenance. It needs no npm publishing token. Verify the published version and its provenance on npm after the run. The workflow does not create a Git tag or GitHub release; handle those separately after publication.

Until the workflow runs successfully, 0.6.1 is a release candidate and has not been published or attested.
