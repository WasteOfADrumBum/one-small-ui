# OneSmallUI v0.6.0: Final Development and Release Readiness Report

Prepared 2026-11-01 by Claude Code (builder). This report is builder evidence. It is not independent
verification, approval or a release decision. Those belong to Joshua Small.

## A. Executive summary

`@onesmall/ui` 0.6.0 is a **hardening release**. It is merged on `main` at candidate commit
**`9a13c9e22d094a95364262a1ae89f666febac892`**, and CI is green on that commit. Nothing has been published:
npm `latest` is still 0.5.0, and there is no `v0.6.0` tag or GitHub release.

- **Security:** the 2 critical dev advisories are gone. 2 moderate dev-only advisories remain, and the production
  dependency audit is clean.
- **Positioning:** floating panels now stay inside short viewports.
- **Compatibility:** React 18 and 19 consumers are tested from the packed tarball on Node 18, 20, 22 and 24.
- **Docs:** the claims were tightened so they match the evidence.

No page-block spec existed, so page blocks were deferred (see F).

**Recommendation: TECHNICALLY READY.** Before publication, the owner still needs to accept the remaining
advisory, do the manual assistive-technology checks, and approve and run the publish (see I and J).

The 2 remaining moderate findings are `minimatch@3` inside `eslint-plugin-jsx-a11y`. This is lint tooling only,
it is never shipped, and it has no fixed upstream release. The only automatic fix is `npm audit fix --force`, which

## D. Accessibility

What the automated evidence shows:

- jest-axe runs on every component (`npm run check`).
- `test:a11y` runs axe 4.14 on every built docs page. It found 0 violations, 0 console errors and 0 broken
  in-page links.
- `test:layout` checks target sizes, reflow and the new short-viewport fixtures in Chromium (1243 checks, 0 failures).
- Contrast is checked against AAA by `check-contrast.mjs`.

The accessibility claim is now "WCAG 2.2 AA, AAA contrast", backed by automated checks. It is not a blanket AAA
claim. One TreeView `label-content-name-mismatch` result is filtered as a documented false positive: the visible
text is the name, and the hidden state text is appended.

**Not done:** no human screen-reader or manual keyboard verification of 0.6.0 (I-4).

**Known limitations:**

- A scrollable Popover body with no focusable content cannot be scrolled from the keyboard in Safari.
- The short-viewport behaviour is verified in Chromium only.
